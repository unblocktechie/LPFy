1. Summary

Chainlink Data Feeds price Uniswap LP collateral for LTV and health checks. Chainlink CRE runs as an automated liquidation keeper: it detects underwater loans and triggers on-chain unwind, then recovers USDC into the pair’s ERC-4626 PairVault.

Problem

Loans go underwater

When collateral value falls, liquidate must run reliably — without opening liquidation to everyone.

CRE

Automated upkeep

Cron → check for liquidatable loans → signed report → on-chain liquidate.

Feeds

Collateral pricing

ETH/USD, USDC/USD, and BTC/USD feeds drive position value for LTV and liquidation health.

Data Feeds decide when a loan is liquidatable. CRE decides who/how liquidation is triggered automatically.

4. CRE liquidation keeper

CRE is not used for lend/borrow UX. Its only job is automated liquidation upkeep.

Read

needsUpkeep

Asks the market if any loan is underwater and returns the first loan id.

Write

writeReport

Sends a signed report with that loan id through the Keystone Forwarder.

Execute

liquidate

Receiver calls the market. Debt returns to PairVault; fee and surplus are split.

After liquidate: debt USDC is pushed into the pair’s PairVault; liquidationFeeBps of surplus → feeTo; remainder → borrower. CRE does not configure fees.

Only the market owner or the authorized CRE receiver may execute liquidate.

  1. Lender funds the PairVault; borrower posts an LP NFT and borrows near LTV.
  2. Loan becomes liquidatable (price move or lower liquidation threshold).
  3. CRE cron finds the loan via needsUpkeep.
  4. CRE writes a report; forwarder delivers it to the receiver.
  5. Market unwinds the NFT, swaps to USDC, repays the vault, then splits surplus.

6. On-chain surface

Receiver

CreLiquidationReceiver

  • needsUpkeep() — CRE read
  • onReport — CRE write (Forwarder only)
  • Decodes loan id and calls liquidate
Market

MarketLendingModule

  • Scans for liquidatable loans
  • liquidate — owner or authorized liquidator
  • Receiver must be authorized
// Receiver (simplified)

function needsUpkeep() external view returns (bool, uint256) {
    return market.findFirstLiquidatableLoan();
}

function onReport(bytes calldata /* metadata */, bytes calldata report) external {
    require(msg.sender == forwarder);
    uint256 loanId = abi.decode(report, (uint256));
    market.liquidate(loanId);
}

7. How the keeper works

The CRE workflow uses a cron trigger plus an EVM client: read upkeep, then write a report when a loan is found. 

flowchart LR
  Cron[Cron schedule] --> Check{Upkeep needed?}
  Check -->|no| Skip[Skip]
  Check -->|yes| Report[Write report with loanId]
  Report --> Chain[On-chain liquidate]

  classDef cre fill:#e8edfb,stroke:#375bd2
  class Cron,Report,Chain cre
Behavior
  • Runs on a fixed schedule (for example every few minutes).
  • If no loan is liquidatable, the run does nothing.
  • If a loan is found, CRE submits a signed report that triggers liquidation.
cre-sdk

Built from the official keeper-bot TypeScript template. Capabilities used: Cron + EVMClient (read + writeReport). 

// cre/liquidation-keeper/workflow.ts (core)

export const onCronTrigger = (runtime) => {
  const receiver = new CreLiquidationReceiver(evmClient, contractAddress)

  const { upkeepNeeded, loanId } = receiver.needsUpkeep(runtime)
  if (!upkeepNeeded || loanId === 0n) return 'Skipped — no upkeep needed'

  const reportData = encodeAbiParameters(
    parseAbiParameters('uint256 loanId'),
    [loanId],
  )

  const writeResult = receiver.writeReport(runtime, reportData, {
    gasLimit: '3500000',  // unwind + swaps need headroom
  })
  // TxStatus.SUCCESS + receiverContractExecutionStatus OK
  return `Liquidated loan ${loanId} — tx: ${txHash}`
}

export function initWorkflow(config) {
  const cron = new cre.capabilities.CronCapability()
  return [cre.handler(cron.trigger({ schedule: config.schedule }), onCronTrigger)]
}

10. Security model

Caller Can liquidate?
Market owner (admin UI) Yes
CreLiquidationReceiver (via CRE Forwarder) Yes — authorized liquidator
Random EOA No — NotLiquidationAuthority
Anyone calling onReport directly No — must be Forwarder

Quick recap

  • Data Feeds → fair LP collateral value → LTV & liquidation health.
  • CRE → scheduled keeper → signed report → authorized on-chain liquidate.
  • Uniswap → LP NFT collateral + unwind/swaps on liquidation.
  • PairVault → recovered debt returns to ERC-4626 lenders; fee split optional.
